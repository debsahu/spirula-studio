# FlexGlue reference and parity fixtures

`ARCHITECTURE.md` describes the model: shapes, constants and what the port can
reuse. This file describes the reference, the fixture format and the tolerance
policy.

| file | what |
|---|---|
| `flexglue_ref.py` | the PyTorch reference: writes stage dumps, the committed fixtures, and timings |
| `compare.py` | scores a stage dump against a reference tree, needs only numpy |
| `fixtures/pairs.json` | the public pairs, as image URLs at pinned commits with sha256 |
| `fixtures/` | the committed tier, generated by `flexglue_ref.py fixtures` |

The weights are fetched from the FlexGlue `v0.1` release and checked by
sha256. They go to `$FLEXGLUE_WEIGHTS` or `~/.cache/flexglue`, and are never
committed. `flexglue.pth` contains the DINOv3 ConvNeXt-B backbone under the
DINOv3 License.

## What the reference is

It is upstream FlexGlue at `c6cbc7a`, in COLMAP's configuration:
- a 512x512 squash;
- keypoints scaled into the 512 frame, with `image_size = (512, 512)`;
- sparse mode with `exact_nn`;
- no head chunking;
- fp32 (`mp=None`);
- COLMAP's thresholds: filter 0.1, max distance 3 px, min covisibility 0.5,
  early-stop decay 0.5.

The stages are taken from upstream's own modules. Every run asserts that they
compose to upstream's `DINOv3Descriptor.encode`, to `MatchHead.forward`, and to
the end-to-end `FlexGlue.match(..., sparse=True)`, and stops if any of those
disagree.

`fixtures` also runs COLMAP's two ONNX graphs on ONNX Runtime's CPU provider,
on the same inputs, and records the agreement in each pair's manifest under
`onnx_check`.

**COLMAP's early stop is not upstream PyTorch's.** Upstream's `early_stop_decay`
checks after every layer 1-8. COLMAP's `flexglue_matcher_early_stop.onnx` checks
only after layers 2, 4, 6 and 8. The `colmap.*` outputs follow the ONNX graph, so
a pair can stop at a layer where upstream PyTorch would not. The `nostop.*`
outputs come from `min_covisibility = 0`, so the readout always runs and is
pinned even on pairs that COLMAP rejects.

## Tiers

Both tiers use the same names and layout.

- **full**: `flexglue_ref.py dump --pairs SPEC --out DIR`. Every tensor is
  written whole as `<name>.npy`, and each image is also saved as `u8.npy`. This
  is the tier to develop against. It is never committed.
- **probe**: `flexglue_ref.py fixtures`, written to `fixtures/` and committed.
  Tensors under 65536 elements are written whole. Larger float tensors are
  written as `<name>.probe_idx.npy`, holding 4096 sorted int32 flat indices
  into the C-order tensor and seeded by the name, plus `<name>.probe_val.npy`
  (f32) and `<name>.stats.json` (shape, dtype, L2 norm, max abs, mean). Images
  are saved as `image.png`, a lossless copy of the decoded RGB the reference
  ran on.

## Layout

```
ROOT/manifest.json                      pairs, torch version
ROOT/images/<stem>/<stage>...           per image: in512 (full tier), u8 / image.png, descriptor stages
ROOT/pairs/<pair>/manifest.json         image stems, files {name: full|probe}, settings,
                                        summary, floor, onnx_check
ROOT/pairs/<pair>/<name>...             per pair stages
```

Conventions:
- **Maps** are `[H, W, C]` f32, channel-last.
- **Tokens** are `[4096, C]` f32, with token `t = y*64 + x`.
- **Points** are in 512-frame pixels with the corner origin, so the top-left
  pixel centre is (0.5, 0.5). The `p2d` and `coarse_p2d` points are instead
  normalized to [-1, 1] in the other image.
- **Indices** are int64, as the ONNX graph's `matches0`. `-1` means none.
- **Masks** are uint8 0/1. **Scalars** are shape `[1]`; `compare.py` also accepts 0-d.

### Per image (`img0.` / `img1.` in a flat dump)

| name | shape | |
|---|---|---|
| `in512` | [512,512,3] | upstream `load_image` /255, then the bilinear squash (full tier only) |
| `desc_norm` | [512,512,3] | `(x - mean) / std` |
| `f4` `f8` `f16` `f32` | [128,128,128] [64,64,256] [32,32,512] [16,16,1024] | ConvNeXt stage outputs |
| `head_stem` | [128,128,128] | LN, conv3x3, LN, GELU |
| `head_fine` | [64,64,512] | `fine_proj(pixel_unshuffle(stem, 2))` |
| `head_x` | [64,64,512] | `head_fine` + the three projected coarse maps |
| `features` | [64,64,256] | descriptor output |
| `size` (pair dir, `img{s}.size`) | [2] | original (w, h) |

### Per pair

| name | shape | |
|---|---|---|
| `kpts{s}` | [M_s,2] | the keypoints fed, 512 frame. **compare.py refuses a dump whose kpts differ by a bit.** |
| `kpts{s}_px` | [M_s,2] | the same keypoints in original pixels |
| `posenc_proj` | [4096,32] | `Wr @ pos`, before cos/sin |
| `tokens{s}` | [4096,512] | after `input_proj` |
| `x{s}_layer{k}`, k=1..9 | [4096,512] | after transformer layer k |
| `cov_layer{k}`, k=1..9 | [1] | covisibility score after layer k, fp32 |
| `search{i}` | [4096,64] | normalized search features of image j, for direction i -> j |
| `fquery{i}` `fmatch{i}` | [M_i,512] | border/bilinear samples of `cf_i` at kpts and of `cf_j` at `coarse_p2d` |
| `logits{i}` | [M_i,4096] | `q . search * temperature` |
| `argmax{i}` `tau{i}` | [M_i] | the entmax window's centre cell and threshold |
| `coarse_p2d{i}` `mass{i}` | [M_i,2] [M_i] | the entmax window readout |
| `offset{i}` | [M_i,2] | OffsetHead, normalized |
| `p2d{i}` `conf{i}` | [M_i,2] [M_i] | the final prediction and confidence |
| `valid{i}` | [M_i] u8 | inside-border checks (min covisibility 0) |
| `nn0` `nn1` | [M0] [M1] | raw argmin of the 4-D squared distance |
| `m0` `m1` | [M0] [M1] | mutual NN, -1 where not mutual (before gating) |
| `nostop.matches0` `nostop.mscores0` `nostop.covisibility_score` | [M0] [M0] [1] | min covisibility 0 |
| `colmap.matches0` `colmap.mscores0` `colmap.covisibility_score` `colmap.stop_layer` | [M0] [M0] [1] [1] | COLMAP's graph with its defaults |
| `colmap_decay02.*` | same | COLMAP's graph with `early_stop_decay 0.2`. The defaults never stop a public pair at an odd layer, so only this setting separates checks at 2/4/6/8 from checks at every layer: `lamar_lookalike` stops at 4 here, and would stop at 3 under every-layer checks. |

A C++ dump is one flat directory: `<name>.npy` per stage, with the image
stages prefixed `img0.` / `img1.`, plus `manifest.json` set to
`{"finished": true, "exit_status": 0, "files": [names]}`. `compare.py flatten`
writes a full-tier reference pair in exactly that layout, which serves as a
worked example.

## Tolerance policy

This follows `tools/roma/compare_torch.py`. Every bar is
`max(fixed bar, 2 x floor)`. The floor is the worst of four draws of torch
against its own CPU fp32 reference: the second torch device (MPS or CUDA), and
three CPU runs with the 512 input perturbed by N(0, 1e-6). The floor is
computed at generation time and stored in the pair manifest, so `compare.py`
never needs torch.

| stage class | metric | fixed bar |
|---|---|---|
| descriptor stages, tokens, layers, search/fquery/fmatch/logits | rel L2 (on probes in the probe tier) | 1e-4 |
| mass, offset, conf, tau, mscores0 | rel L2 | 1e-3 |
| coarse_p2d, p2d | EPE in 512-frame px, p50 / p99 | 0.01 / 0.1 |
| cov_layer*, covisibility_score | abs | 1e-4 |
| argmax, nn*, m*, valid, matches0 | fraction of entries that differ | 0.002 |
| stop_layer | exact | 0 |

Keypoint indices (`matches0`, `m0`, `m1`, `nn0`, `nn1`) are compared **modulo
duplicate keypoints**. COLMAP's SIFT emits one keypoint per dominant
orientation, so about 20% of real keypoints share their exact location with
another. Copies get identical predictions, so which copy wins the mutual NN is
an argmin tie, and any copy is correct. On real 8192-keypoint pairs, ONNX
Runtime and torch disagreed on 22-115 raw `matches0` rows per pair, and all of
those disagreements were ties between copies: there were 0 differing pairs once
copies were identified. The public fixtures use deduplicated keypoints, so
they are unaffected.

The fixed bars are the same as RoMa's f32 bars. The 1e-3 for readout values and
the 0.002 discrete fraction are **choices, not measurements**. They are widened
by the floor wherever torch disagrees with itself by more.

```bash
uv run tools/flexglue_ref/compare.py check --dump DUMP --pair berlin              # committed tier
uv run tools/flexglue_ref/compare.py check --dump DUMP --ref FULLROOT --pair berlin
```

`--expect-gated N` adds a failing row when the gated count is not N. A dump that
lost a stage scores fewer rows and can otherwise pass; the six committed pairs
gate 91 rows each in the fp32 tier.

### The fp16 tier

`--tier fp16` scores a run of the opt-in fp16 matcher (`flexglue_test --fp16`,
MPSGraph fp16 attention and GEMM on Apple) against the same fp32 reference. fp16
operands cannot meet the bars above: PyTorch's own fp16 autocast of the
transformer fails 33 of 89 gated rows on `berlin` and 41 on `sacre_x_dsc`. This
tier gates only what a match run ends in and reports every other stage:

| stage | metric | fp16 bar |
|---|---|---|
| every `matches0` (`nostop`, `colmap`, `colmap_decay02`) | mutual-match pairs that differ, mod copies | 0.01 |
| every `stop_layer` | exact | 0 |

The bars were fixed before any fp16 run of ours was scored. PyTorch's fp16
autocast dump passes them on `berlin`, `sacre_x_dsc` and `lamar_lookalike`, with
0 differing matches. They are blind by construction to a change that leaves the
matches alone. Of six known model mutants scored on those three pairs,
`no_qk_norm` and `backbone_ln_eps` fail them on two pairs, `argmax_readout` and
`unshuffle_order` on one, and `zero_padding` and `no_offset` on none, while the
fp32 tier fails every one on every pair by 4-81 rows. A pass here says the
matches are the same, not that the model is.

```bash
uv run tools/flexglue_ref/compare.py check --dump DUMP --pair berlin --tier fp16
```
